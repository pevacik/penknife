# Penknife

Веб-приложение в стиле маркетплейса для менеджеров.

## Стек

- **Frontend**: Vite + React + TypeScript, архитектура [Feature-Sliced Design]
- **Backend**: Express-сервер + PostgreSQL (через Prisma ORM).

## Структура

```
apps/
├── web/       # фронтенд (FSD)
└── server/    # API-сервер
```

## Документация

Подробная архитектура, структура кода и руководство по разработке — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Запуск

1. Установить зависимости и поднять базу данных (нужен Docker):

```bash
npm install
docker compose up -d
```

2. Подготовить схему БД (первый раз) и при необходимости импортировать старые данные:

```bash
cd apps/server
npx prisma generate
npx prisma db push
npm run db:import   # необязательно: перенос данных из data/products.json
```

3. Создать пользователя для входа (пароль — не короче 12 символов):

```bash
npm run user:create --workspace server -- admin
```

Первый пользователь в пустой БД получает роль `admin`. Остальные роли — `user` и `viewer` (см. «Роли и права»).

4. Запустить приложение:

```bash
npm run dev
```

- Frontend: http://localhost:5173
- Backend:  http://localhost:3001

Фронт ходит на бэкенд через Vite-прокси (`/api`). Для удалённого сервера лучше отдавать фронт тем же Express (или проксировать `/api` через nginx): cookie сессии работает на одном origin. Если API на другом домене, потребуются `SameSite=None; Secure` и CORS с `credentials`.

## База данных

- PostgreSQL запускается в Docker (`docker-compose.yml`), данные — в volume `penknife_pgdata`.
- Порт БД опубликован только на loopback (`127.0.0.1:5432`) — из локальной сети база недоступна.
- Пароль задаётся в `.env` в корне (`POSTGRES_PASSWORD`, образец — `.env.example`) и дублируется в `apps/server/.env` (`DATABASE_URL`). Для существующего volume пароль меняется через `ALTER USER`.
- Схема описана в `apps/server/prisma/schema.prisma` (модели `Product`, `ProductImage`, `Comment`, `CommentImage`, `User`, `Session`, `AuditLog`).
- Для показа паролей в админ-панели задайте `PASSWORD_ENCRYPTION_KEY` в `apps/server/.env` (длинная случайная строка; см. `.env.example`). Без ключа пароли не показываются, но вход и смена работают.
- Изображения лежат на диске в `apps/server/uploads/`, в БД хранятся только локальные URL (`/uploads/...`). Картинки, добавленные по ссылке, сервер скачивает и сохраняет к себе.
- Для каждой картинки генерируются производные размеры (WebP: `thumb` 480 px, `medium` 1280 px) в `apps/server/uploads/.variants/`; они раздаются через `/media/:variant/:file` с годичным `immutable`-кэшем.

## Возможности

- Вход по логину и паролю (сессия в httpOnly-cookie, пароли — scrypt). Все данные и картинки доступны только после входа.
- Каждый пользователь может самостоятельно сменить пароль: «Меню» → «Сменить пароль» (новый пароль, минимум 12 символов; старый не запрашивается).
- Строка поиска сверху (ищет по названию, тиражу, тегам, стране и тексту комментариев).
- Сайдбар с фильтрами слева: «Сроки» (Россия/Китай/оба), «Сделать 50» (Пусто/Да), «Тираж» (подходят изделия с тиражом не больше указанного), «Бюджет» (по цене, сортировка от большего к меньшему).
- Корзина: кнопка «в корзину» на карточке и иконка корзины в шапке. В корзине позиции можно удалять и редактировать комментарий (цена/тираж/срок подставляются автоматически); кнопка «Скачать список» генерирует PDF: картинка вписывается в 16:9-рамку на всю ширину (без кропа и растяжения, при других пропорциях — по центру с «воздухом»), под ней до 4 строк комментария.
- Кнопка «Добавить карточку» — создаёт пустую карточку.
- Кнопка «CSV» рядом — окно импорта/экспорта карточек через CSV (разделитель `;`, колонки: `id`, название, цена, тираж, сделать 50, срок производства, теги, изображения, комментарии). При импорте карточки с существующим `id` обновляются (без дублей), с пустым `id` — создаются заново (вместе с изображениями и комментариями).
- Клик по карточке открывает страницу `/products/:id`:
  - изображения (несколько, загрузка файлом, по ссылке — сервер скачивает картинку и хранит её локально — или вставкой из буфера обмена); клик по миниатюре открывает просмотр с листанием;
  - поле «Цена» (₽, только цифры);
  - поле «Тираж» (только цифры);
  - поле «Сделать 50» (да/нет, по умолчанию нет);
  - поле «Срок производства» (Китай/Россия, по умолчанию Россия);
  - поле «Теги» (слова через запятую);
  - комментарии с заголовком и изображениями: подписываются автором и временем, любой пользователь с правом `manageComments` может отредактировать любой комментарий (в том числе чужой), удалять может только админ; у изменения сохраняется автор (`updatedByName`) и время; изображения — загрузка файлом или вставкой из буфера обмена, просмотр по клику, удаление по одному (только админ);
  - кнопка удаления карточки (только админ);
  - авторство карточки («Создал …», «Изменил …») и ссылка «История карточки» в журнал — только для администратора; остальным этот блок полностью не отображается.

## Роли и права

| Действие | `admin` | `user` | `viewer` |
|---|---|---|---|
| Смотреть карточки, картинки, комментарии | ✅ | ✅ | ✅ |
| Скачать PDF из корзины | ✅ | ✅ | ❌ |
| Создать/редактировать карточку | ✅ | ✅ | ❌ |
| Картинки: загрузка, импорт по ссылке | ✅ | ✅ | ❌ |
| Картинки: удаление | ✅ | ❌ | ❌ |
| Комментарии: добавление | ✅ | ✅ | ❌ |
| Комментарии: редактирование | ✅ (любые) | ✅ (любые, в т.ч. чужие) | ❌ |
| Комментарии: удаление | ✅ | ❌ | ❌ |
| Удалить карточку | ✅ | ❌ | ❌ |
| CSV импорт/экспорт (`GET /api/products/all`) | ✅ | ❌ | ❌ |
| Управление пользователями | ✅ | ❌ | ❌ |
| Журнал действий (`/admin/audit`) | ✅ | ❌ | ❌ |
| Авторство карточки и «История карточки» | ✅ | ❌ | ❌ |

`viewer` — режим «только просмотр» (например, для демонстрации): карточки открываются, но поля не редактируются. Кнопки действий остаются видимыми, но при клике показывают «У вас нет прав для этого действия» и не отправляют запрос.

Помимо роли, администратор может выдавать и отзывать **персональные права** в разделе «Пользователи»: например, разрешить обычному пользователю создавать карточки, управлять изображениями или комментариями, экспортировать PDF. Эффективные права = база роли + выданные − отозванные. Структурные права (`viewProducts`, `deleteProduct`, `deleteImages`, `deleteComments`, `csv`, `manageUsers`, `viewAudit`) персонально не переопределяются: просмотр есть у всех вошедших, удаление и CSV — только у `admin`.

### Админ-панель

Администратор видит в меню «Меню» пункты «Пользователи» (`/admin/users`) и «Журнал действий» (`/admin/audit`):

- список пользователей: логин, роль, доп. права, активные сессии, дата создания;
- «Добавить пользователя» — логин, пароль (мин. 12), роль;
- «Права» — роль и чекбоксы эффективных прав: можно выдать право сверх роли или отозвать базовое; смена роли завершает сессии пользователя;
- «Пароль» — показать сохранённый пароль (при настроенном `PASSWORD_ENCRYPTION_KEY`); если пароль задан до включения отображения, попросит сменить его;
- «Смена пароля» — задать новый пароль (сессии пользователя завершаются, старый пароль не требуется);
- «Разлогинить» — завершить все сессии пользователя;
- «Удалить» — удаление вместе с сессиями.

В таблице также видно, когда и кем обновлён пароль: «сам · дата», «admin · дата» или «CLI · дата». Сами пароли нигде не отображаются.

Нельзя изменить или удалить собственную учётную запись и снять роль/удалить последнего администратора — защита от блокировки.

Пользователи создаются и меняются через CLI:

```bash
npm run user:create --workspace server -- admin               # первый в пустой БД станет admin
npm run user:create --workspace server -- manager             # роль user
npm run user:create --workspace server -- demo --role=viewer  # только просмотр
npm run user:create --workspace server -- --list              # список пользователей
npm run user:create --workspace server -- --delete=demo       # удалить (последнего admin удалить нельзя)
```

Без `--role`: первый пользователь в пустой БД становится `admin`, остальные — `user`. Повторный запуск меняет пароль/роль и разлогинивает все сессии пользователя.

## API

| Метод  | Путь                          | Описание                          |
| ------ | ----------------------------- | --------------------------------- |
| POST   | `/api/auth/login`             | Вход (`{ username, password }`), ставит httpOnly-cookie |
| POST   | `/api/auth/logout`            | Выход, удаляет сессию             |
| GET    | `/api/auth/me`                | Текущий пользователь (роль + эффективные права) |
| POST   | `/api/auth/password`          | Сменить свой пароль (`{ newPassword }`, старый не требуется) |
| GET    | `/api/users`                  | Список пользователей (только `manageUsers`) |
| GET    | `/api/users/:id/password`     | Показать сохранённый пароль (только `manageUsers`) |
| POST   | `/api/users`                  | Создать пользователя              |
| PATCH  | `/api/users/:id`              | Роль, пароль и персональные права |
| DELETE | `/api/users/:id`              | Удалить пользователя              |
| POST   | `/api/users/:id/logout`       | Завершить все сессии пользователя |
| GET    | `/api/products`               | Список карточек (пагинация: `page`, `limit`, `query`, `country`, `circulation`, `maxBudget`, `make50`) |
| GET    | `/api/products/all`           | Все карточки (для CSV-экспорта)   |
| GET    | `/api/products/:id`           | Одна карточка                     |
| POST   | `/api/products`               | Создать карточку                  |
| PATCH  | `/api/products/:id`           | Обновить поля карточки            |
| DELETE | `/api/products/:id`           | Удалить карточку                  |
| POST   | `/api/products/export-pdf`    | PDF: картинка 16:9 (вписывается по центру без кропа) + до 4 строк комментария (`{ items: [{ id, comment }] }`) |
| POST   | `/api/products/:id/comments`  | Добавить комментарий (подписывается автором) |
| PATCH  | `/api/products/:id/comments/:commentId` | Редактировать комментарий (`manageComments`, любой автор) |
| DELETE | `/api/products/:id/comments/:commentId` | Удалить комментарий (только admin) |
| DELETE | `/api/products/:id/comments/:commentId/images/:imageId` | Удалить изображение комментария (только admin) |
| POST   | `/api/products/:id/images`    | Добавить изображение по ссылке    |
| DELETE | `/api/products/:id/images/:imageId` | Удалить изображение карточки (только admin) |
| GET    | `/api/audit`                  | Журнал действий (`viewAudit`; фильтры `action`, `search`, `from`, `to`, `productId`, `page`, `limit`) |
| GET    | `/api/audit/stats`            | Статистика журнала за период (`viewAudit`) |
| POST   | `/api/uploads` (multipart)    | Загрузить файл изображения        |
| POST   | `/api/uploads/from-url` (JSON) | Скачать изображение по ссылке и сохранить локально (`{ url }`) |
| GET    | `/media/:variant/:file`       | Производный размер картинки: `thumb` (480 px) или `medium` (1280 px), WebP |
| GET    | `/api/health`                 | Проверка работоспособности        |

Данные хранятся в PostgreSQL (Docker, БД `penknife`), загруженные изображения — в `apps/server/uploads/` (папка создаётся автоматически).

Все маршруты `/api`, `/media` и `/uploads`, кроме `/api/health` и `/api/auth/*`, требуют активной сессии. Доступ к операциям проверяется по правам: `createProduct`, `editProduct`, `deleteProduct`, `manageImages`, `deleteImages`, `manageComments`, `deleteComments`, `csv`, `exportPdf`, `viewAudit`; управление пользователями (`/api/users*`) — только `manageUsers` у роли `admin`. Структурные права (`deleteProduct`, `deleteImages`, `deleteComments`, `csv`, `manageUsers`, `viewAudit`) есть только у `admin`.

### Безопасность

- Пароли для входа хранятся как scrypt-хэши (`scrypt$N$r$p$salt$hash`), проверка — `timingSafeEqual`. Для показа в админ-панели дополнительно хранится копия пароля, зашифрованная AES-256-GCM ключом `PASSWORD_ENCRYPTION_KEY`; без ключа показ отключён, а пароли, заданные до включения показа, становятся доступны после следующего входа или смены.
- Три роли (`admin`, `user`, `viewer`) и персональные права проверяются серверным `requirePermission`; кнопки в UI видны всем, но без права показывают toast и не делают запрос. Прямой запрос всё равно получит `403`.
- Журнал действий (`AuditLog`) фиксирует вход/выход, создание/изменение/удаление карточек, комментариев, изображений и пользователей, а также просмотр паролей администратором. В записи хранятся `actorId`/`actorName`, название объекта, `details` (до/после) и IP; записи не удаляются каскадом и переживают удаление пользователя или карточки.
- Сессия — случайный токен в httpOnly-cookie `penknife_sid` (`SameSite=Lax`, `Secure` в проде), в БД лежит только SHA-256 токена; `POST /api/auth/logout` удаляет сессию, смена пароля разлогинивает все устройства.
- Самостоятельная смена пароля: старый пароль не запрашивается, новый — от 12 символов; после смены остальные сессии завершаются, текущая остаётся. Показ пароля в админке доступен только роли `admin` и фиксируется в журнале.
- Ограничение попыток входа: 5 неудач на IP+логин за 15 минут (`429`), общий лимит API — 300 запросов/мин на IP.
- CORS ограничен allowlist-ом (`CORS_ORIGINS`), для изменяющих запросов проверяется `Origin` (в production).
- Ошибки 500 отдают нейтральное сообщение, детали пишутся только в лог сервера; `X-Powered-By` отключён, включены security-заголовки и CSP в проде.
- Картинки (`/media`, `/uploads`) тоже закрыты входом и кэшируются приватно (`Cache-Control: private`).

## Скрипты

- `npm run dev` — запуск фронта и сервера одновременно.
- `npm run build` — сборка фронта.
- `npm run build:server` — сборка сервера.
- `npm run start` — запуск собранного сервера.
- `npm run prisma:generate --workspace server` — генерация Prisma Client.
- `npm run db:push --workspace server` — синхронизировать таблицы со схемой.
- `npm run prisma:migrate --workspace server` — создать/применить миграцию.
- `npm run db:import --workspace server` — импорт данных из `data/products.json`.
- `npm run images:variants` — сгенерировать варианты всех картинок в `uploads/` (`thumb`, `medium`, JPEG для PDF) и вывести экономию по весу.
- `npm run user:create --workspace server -- <логин> [--role=admin|user|viewer] [--password=...]` — создать пользователя или сменить пароль/роль (пароль спросит скрыто; можно передать `ADMIN_PASSWORD`).
- `npm run user:create --workspace server -- --list` — список пользователей (роль, доп. права, отозванные, сессии); `-- --delete=<логин>` — удалить пользователя.
- `npm run user:create --workspace server -- <логин> --grant=createProduct,manageComments --revoke=editProduct` — выдать/отозвать персональные права из CLI (страховка, если админка недоступна).
